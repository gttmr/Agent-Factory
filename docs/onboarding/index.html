Agent Factory 온보딩 가이드

ADK, A2A, MCP, EAI 같은 용어가 처음이라도 이 워크벤치로 어떻게 요구사항을 분석하고 4단계 DLC 산출물로 검토한 뒤 ADK Runtime Handoff까지 가는지 단계별로 따라갈 수 있도록 만든 가이드다. 9개의 문서를 순서대로 읽으면 된다.

이 가이드가 답하는 질문

  • “Agent랑 Workflow랑 Adapter가 도대체 뭐가 다른가?”
  • “이 요구사항은 workflow_kind를 graph로 둬야 하나, dynamic으로 둬야 하나?”
  • “Remote A2A는 언제 쓰는가? 그냥 워크플로우랑 뭐가 다른가?”
  • “MCP, EAI, Callback Broker, Context Manager — 다 들어봤는데 워크벤치에서는 어디에 들어가는가?”
  • “needs_info 후보와 Runtime 계약은 어떻게 풀고, 언제 ADK Runtime Handoff로 넘어갈 수 있는가?”
  • “analysis-result.json과 af-run-manifest.json은 워크벤치에서 어떻게 이어지는가?”

현재 운영 모델

raw requirement → af-analyze-requirement → af-design-boundaries → approved scaffold-plan + ADK Runtime Handoff → af-build-runtime-stub → af-verify-feedback

워크벤치는 이 흐름의 산출물을 읽고 검토 상태를 시각화한다. 특히 analysis-result.json은 분석/설계 artifact 본문이고, af-run-manifest.json은 DLC 단계·승인·검증 상태를 연결하는 가벼운 manifest다.

i

단일 기능 생성성이 아니라 Agent 시스템 생산성이 목표다. 한 개 Agent는 기존 AI DLC 흐름으로 충분할 수 있지만, 수백 개 Agent는 연결·스키마·MCP·재사용까지 lifecycle 산출물로 관리해야 한다.

가이드 지도

1장

ADK 기본 개념

Agent, Workflow, Adapter, Remote A2A, MCP, A2A, EAI, Callback이 무엇이고 워크벤치에서 어떤 자리에 놓이는지 그림으로 본다.

2장

워크벤치 한 바퀴

요구사항 접수 → 분석 결과 → 모듈 검토 → Graph IR → Runtime/Remote 계약 → 카탈로그 → 저장 → ADK 소스 생성 흐름을 본다.

3장

Taxonomy 결정

module_category와 subtype을 어떻게 선택하는지 결정표와 미니 분류기로 익힌다.

4장

Workflow 종류 고르기

orchestration / graph / dynamic / unknown 결정 트리.

5장

Process Flow와 Graph IR

node, edge, container 의미와 fan-out / loop / human input / Remote A2A 마커.

6장

Module Review Board

승인/보류/반려/needs_info 판단, Resolution Draft, 2계층 missing-info 게이트.

7장

Runtime 계약

MCP, EAI/Legacy Adapter, Context Manager, Callback Broker, ADK callback, async resume를 어떻게 승인 게이트로 검토하는지.

8장

검증과 ADK Runtime Handoff

manifest 승인, scaffold-plan, source generation gate, smoke 일괄 실행, 검증 명령.

9장

용어집

가이드 안에서 쓴 모든 용어를 한 곳에서 검색.

읽기 순서 추천

A

처음이면 1장 → 2장 순서로

ADK 개념을 먼저 잡고, 워크벤치 단계가 어디에 매핑되는지 한 번에 본다.

B

실제 분석을 시작하면 3 → 4 → 5장

실제 요구사항을 분류하고 워크플로우 종류를 고르고 Graph IR로 표현하는 흐름이다.

C

리뷰와 산출에 들어가면 6 → 7 → 8장

승인 게이트, 런타임 계약, 핸드오프까지 가서 끝낸다.

D

막히면 9장 용어집

검색창에서 키워드를 입력해서 정의를 빠르게 확인한다.

중요한 첫 번째 원칙

!

Raw requirement는 직접 코드 생성으로 이어지지 않는다.

Agent Factory는 “요구사항 → 자동 코드 생성” 도구가 아니다. 요구사항을 검토 가능한 산출물로 바꾼 다음, 승인된 후보·Runtime 계약·Graph IR·manifest 승인 상태가 맞을 때만 ADK Runtime Handoff(소스 번들 + smoke 검증)로 흘려보낸다. 이 가이드 전체가 이 원칙을 지키기 위한 화면과 결정들을 다룬다.

i

이 워크벤치 UI는 한국어다. 가이드의 용어도 화면 라벨과 가능한 한 맞춘다. 영문 enum 값(module_category, adapter_kind 등)은 그대로 사용한다 — 이것이 schema와 validator의 단일 단어다.
