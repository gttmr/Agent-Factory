9. 용어집

이 가이드와 워크벤치 화면에 등장하는 모든 용어를 한 곳에서 검색한다. 키워드를 입력하면 실시간으로 필터링된다.

ADK Agent Development Kit

Google이 만든 에이전트 구축 프레임워크. 이 워크벤치의 baseline은 ADK Python 2.0 GA다. LLM Agent, Workflow Agent, Tools, State/Artifact/Event를 제공한다.

ADK Runtime Handoff

승인된 workbench artifact와 manifest approval만 입력으로 받아 runtime stub source bundle을 만드는 review-gated handoff(기본 smoke TODO; 승인된 runnable 모드는 실행형 ADK Workflow). 배포가 아니다.

af-run-manifest.json

Skill-led DLC 실행의 단계 상태, 출력 경로, 승인 상태, 검증 결과를 연결하는 lightweight manifest. Workbench는 browser file import로 이 파일을 읽고 DLC 상태 요약을 표시한다.

af-analyze-requirement / af-design-boundaries / af-build-runtime-stub / af-verify-feedback

Agent Factory 4단계 DLC skill. 분석 artifact 생성, boundary/runtime/catalog 설계 승인, ADK runtime stub 생성(기본 smoke TODO; runnable 모드는 실행형 Workflow), 검증과 feedback 기록을 순서대로 담당한다.

A2A Agent-to-Agent protocol

에이전트 간 통신 프로토콜. Agent Card, Task lifecycle, message/artifact 계약을 정의한다. 워크벤치에서는 remote_a2a 후보의 계약 검토와 catalog 안의 공통 Workflow runtime binding으로 등장한다.

Agent Card

원격 에이전트가 자신의 capability/interface/auth를 알리는 discovery metadata. Remote A2A 후보를 승인하려면 이 정보가 필요하다.

agent_kind

module_category: agent일 때 subtype. specialist 또는 shared.

adapter_kind

module_category: adapter일 때 subtype. legacy_api, retrieval, rule_registry, data_query, template, computation, external_service, unknown.

AnalysisResult

워크벤치가 raw requirement를 정규화해 만든 canonical combined artifact. normalized requirement, evidence, module candidates, A2A contracts, runtime contracts, Graph IR을 포함한다. 파일명은 보통 analysis-result.json이며 Stage Runner proposal이 적용된 뒤 canonical artifact가 된다.

Analyze Skill Runner

/af/:reqId/analyze의 첫 패널. raw requirement, domain, model, seed catalog를 서버 Stage Runner에 보내고 proposed analysis-result.json을 만든다.

BuildWorkbench

/af/:reqId/build route. 승인된 artifact에서 scaffold-plan.json을 만들고 runtime-stub/ source bundle을 생성한다.

acceptedMissing

AnalysisResult 행마다 “수용” 토글이 만드는 배열. requirement-level missing-info의 soft attestation 기록.

Callback Broker

비동기 callback 결과를 다시 에이전트 흐름으로 라우팅하는 책임. Runtime 계약 종류 중 하나.

Catalog

재사용 가능한 agents/workflows/adapters/remote_a2a runtime contract YAML 모음. catalog/ 디렉터리에 있다.

catalog_entry_id

ModuleCandidate가 catalog 항목에서 온 경우 그 출처 id. 있으면 DesignWorkbench(/af/:reqId/design)의 모듈 검토 패널에서 카탈로그 계약으로 분기된다.

chat-smoke 워크벤치 자체 챗 제거 → ADK dev UI 링크

generated ADK app에 대해 session을 만들고 /run endpoint를 호출해 응답을 확인하던 dev smoke. PR6에서 adk web iframe 임베드와 Smoke 일괄 실행 매크로가 제거됐고, 이후 워크벤치 자체 챗(session/message)도 제거됐다. 대신 실행 화면(/af/:reqId/run)이 adk api_server --with_ui를 띄우고 ADK가 제공하는 공식 dev UI(채팅·세션·이벤트·트레이스)로 새 탭 링크한다. 코드 레벨 smoke(pytest 등)는 생성된 번들에서 직접 돌린다.

실행 (RunSandbox)

/af/:reqId/run route. 승인 게이트가 없는 도구 화면이다. runtime-stub/ 생성 후 runtime-stub/.venv에 ADK dependency를 설치하고, 로컬 adk api_server --with_ui(8765)를 시작/중지하며 상태를 폴링하고, ADK 공식 dev UI(web_url)를 새 탭으로 링크한다. 보조 nav 항목일 뿐이며 afRunStageIds(=manifest 스테이지 스키마/게이트 칩)에 포함되지 않는다.

StageShell

packages/web/src/layout/StageShell.tsx. 4개 스킬 스테이지가 공유하는 셸 — 좌측 스텝 레일(1실행 · 2검토 · 3승인, Verify는 게이트가 없어 실행·기록 2스텝), 항상 보이는 산출물 요약 strip, "다음에 할 일" 가이드, 하단 next-action CTA로 구성된다. 활성 스텝은 얕은 ?step= 쿼리(useStageStep)이고 첫 미완료 스텝으로 착지한다. 스텝 status는 manifest.approvals.* + 산출물 존재에서 읽기만 하고 게이트를 재계산하지 않는다.

Codex CLI

분석/설계 Stage Runner가 내부에서 실행할 수 있는 CLI. /api/analyze-requirement SSE endpoint는 direct/internal analyzer primitive로 남아 있지만, 기본 UI 경로는 /api/af/:reqId/stages/analyze/run이다.

Design Skill Runner

/af/:reqId/design의 첫 패널. analysis_reviewed=true인 canonical analysis를 기준으로 module boundary, Graph IR, Runtime 계약, A2A 계약 변경을 proposed artifact로 만든다.

DLC

Agent Factory에서는 분석, 설계, 개발, 검증으로 이어지는 delivery lifecycle을 뜻한다. 한 기능 생성이 아니라 여러 Agent/Workflow/Adapter/Remote A2A의 연결, 스키마, MCP, 재사용 상태까지 산출물로 관리한다.

container_kind

Graph IR container의 종류. graph_workflow, dynamic_workflow, parallel_region, loop_region, human_review_region, remote_boundary.

Context Manager

여러 호출에 걸친 상태(session/temp/user/app)의 소유와 lifecycle을 관리하는 책임. Runtime 계약 종류 중 하나.

dynamic (workflow_kind)

Python 코드(조건/loop/recursion/ctx.run_node)가 런타임 경로를 결정해야 할 때. Graph IR에서는 dynamic_workflow container.

EAI Enterprise Application Integration

기업 내 시스템들을 연결하는 통합 버스/미들웨어. 워크벤치에서는 adapter_kind: legacy_api와 Runtime 계약(Legacy Adapter contract)으로 다룬다.

edge_kind

Graph IR edge의 데이터/제어 채널 종류. event_output, event_message, session_state, temp_state, user_state, app_state, artifact, route, control, remote_a2a.

execution_semantics

edge가 어떤 흐름 의미를 갖는지. normal_transition, fan_out, fan_in, loop_back, loop_exit, conditional, boundary_crossing.

fan_out / fan_in / join

병렬 흐름의 시작/모음/합류. parallel_region container와 함께 사용한다.

graph (workflow_kind)

ADK 2.0 graph workflow처럼 node와 edge, route, join, loop, human input이 명시적인 설계 산출물일 때. Source generator는 검토된 Graph IR edge를 generated workflow skeleton edge로 사용한다.

Graph IR

Process Flow의 내부 표현. node/edge/container로 흐름을 정의한다. processFlow라는 필드 이름은 호환성 때문에 유지된다.

human_input

사람 승인/보완 요청을 graph 안의 일시정지/재개 노드로 표현. human_review_region container 안에 둔다.

legacy_recommended_type

마이그레이션용 메타데이터. primary classifier로 다시 쓰지 않는다.

loop_region / loop_control / loop_back / loop_exit

반복 흐름의 container와 edge. 정해진 종료 조건이 있는 반복을 static graph로 표현할 때 사용한다.

MCP Model Context Protocol

LLM이 외부 도구/데이터에 접근하기 위한 표준 프로토콜. inputSchema/outputSchema로 tool을 정의한다. 워크벤치에서는 대부분 adapter로 분류된다.

missing_information (요구사항 수준)

evidence.missing_information. AnalysisResult에서 “수용” 토글이 가능한 soft gate. scaffold 생성을 막지 않는다.

missing_information (후보 수준)

ModuleCandidate.missing_information. unresolved needs_info와 함께 hard gate를 만든다. af-design-boundaries skill이나 외부 producer가 Resolution Draft를 반영하면 비워지고 항목은 resolved_missing_information으로 이동한다.

module_category

최상위 분류. agent, workflow, adapter, remote_a2a 4개만 허용.

ModuleCandidate

분석이 만든 후보 모듈 하나. DesignWorkbench(/af/:reqId/design)의 모듈 검토 패널에서 status를 결정한다.

needs_info (status)

후보 승인 전 추가 정보가 필요한 상태. Resolution Draft 절차로 푼다.

node_kind

Graph IR node의 종류. input, output, agent, function, tool, adapter, human_input, workflow, remote_a2a, join, router, loop_control.

orchestration (workflow_kind)

상위 조율 책임은 보이지만 graph topology가 아직 핵심 산출물이 아닐 때. 구현 handoff에서 추가 설계가 필요.

processFlow

AnalysisResult.processFlow. 내부 shape는 Graph IR이지만 필드명은 마이그레이션 호환 때문에 유지된다.

proposed-artifacts

Stage Runner run folder 안의 적용 전 산출물 디렉터리. reviewer가 diff/preview를 확인하고 apply해야 canonical artifact로 반영된다.

diff-summary.json

Stage Runner run의 proposed artifact가 canonical artifact와 어떻게 다른지 요약한 evidence 파일. validation 상태와 apply 가능 여부 판단에 쓰인다.

remote_a2a (module_category)

독립 owner를 가진 원격 에이전트와의 protocol boundary. high-friction. risk_level: high와 owner/agent_card/auth/task_lifecycle/timeout/retry/fallback/audit 필수.

remote_boundary

Graph IR container 종류 중 하나. remote_a2a 노드를 감싼다.

remote_contract_kind

module_category: remote_a2a일 때 subtype. a2a 또는 unknown.

Resolution Draft

LLM이 만든 needs_info 후보의 검토 초안. PR6 마이그레이션 이후 워크벤치 UI 안에는 “해결 초안 생성 / 반영 적용” 인스펙터가 없다. Draft 적용은 af-design-boundaries skill(또는 동일 schema를 emit하는 외부 producer)이 missing_information_resolution, resolved_missing_information, resolution_applied_at, schema_review_state: applied, smoke_spec을 채워 analysis-result.json을 다시 PUT하는 식으로 처리한다.

resolved_missing_information

반영 적용 시 기존 missing_information이 이동되는 자리. 흔적으로 남는다.

risk_signals

analyzer가 후보에 붙이는 위험 신호. personal_data, financial_data, credit_decision_support, customer_impact, external_message, transaction_write, human_approval_required, audit_required. 자동 차단은 아니다.

route_condition

edge_kind: route의 필수 metadata. 어떤 조건일 때 이 edge가 선택되는지 적는다.

run artifact

Stage Runner 한 번의 실행을 설명하는 파일 묶음. request.json, events.jsonl, result-summary.json, diff-summary.json, proposed-artifacts/, 실패 시 diagnostics.md를 포함한다.

runtimeContracts

AnalysisResult.runtimeContracts. MCP/EAI/Legacy adapter contract, Context Manager, Callback Broker, ADK callback, async resume의 review artifact. 현재 DesignWorkbench의 Runtime 계약 탭에서 readiness를 검토하고, 필수 계약은 contract_status: approved가 되어야 scaffold/source generation을 통과한다.

runtime_binding

catalog 항목의 호출 방식. mcp, remote_a2a, unresolved. module_category와는 다르다.

runtime_mock

seed catalog가 가질 수 있는 deterministic synthetic 응답. local smoke를 위한 test double. private endpoint/credential/실데이터 금지.

scaffold-plan

scaffold-plan.json. 승인된 workbench artifact만 입력으로 받는 ADK Runtime Handoff의 검토 게이트 계약. manifest approval, 승인된 module candidate, approved runtime contract, Graph IR coverage와 함께 source generation gate가 된다.

Stage Runner

Analyze/Design 화면에서 서버에 skill 실행을 요청하는 공통 실행 모델. run evidence를 runs/<stage>/<run-id>/에 남기고 canonical artifact는 diff/preview 후 apply할 때만 바꾼다.

stage_runs

af-run-manifest.json의 optional 실행 요약 필드. 최근 run id, status, output path를 담지만 approval gate를 대체하지 않는다.

scaffoldReady

SavedAnalysisRecord fixture 필드. can_generate_source && Graph IR errors.length === 0. PR6 이후 워크벤치는 이 record로 landing step을 분기하지 않으며, scripts/validate-artifacts.mjs가 templates/saved-analysis-fixtures/의 regression smoke로만 검증한다.

SavedAnalysisRecord UI 사용 중단, fixture 전용

이전 워크벤치가 localStorage에 저장하던 분석 record(catalogEntries snapshot, activeStep, scaffoldReady 등). PR6 마이그레이션 이후 워크벤치는 in-browser save record를 운용하지 않으며, 단일 저장소는 artifacts/af/<req-id>/다. shape 자체는 templates/saved-analysis-fixtures/에 fixture로 남아 scripts/validate-artifacts.mjs regression에서만 쓴다.

schema_review_state

후보의 schema 검토 상태. Resolution Draft 반영 시 applied가 된다.

Schema Tree PR6 이후 워크벤치에서 제거

이전 Module Review Inspector에서 object/array<object> 입력/출력을 펼침 가능한 트리로 보여주던 컴포넌트. PR6 마이그레이션에서 Module Review 인스펙터와 함께 제거됐다. 현재 입력/출력은 DesignWorkbench의 GraphInspector에서 표시한다.

Smoke 일괄 실행 macro PR6 이후 워크벤치에서 제거

이전 ADK Runtime Handoff 화면의 매크로. generate → install → start-web → check-web → chat-smoke를 순차 실행하고 첫 실패에서 정지했다. PR6 마이그레이션에서 매크로와 단계별 버튼 UI는 모두 제거됐고, 현재 BuildWorkbench는 runtime-stub/build만, VerifyWorkbench는 고정 allow-list 세 명령만 실행한다.

smoke_spec

승인된 후보의 chat smoke 계약 데이터. synthetic input, sample message, expected output shape를 포함한다. analysis-result.json과 catalog 항목에는 그대로 남아 있으며, 실행 화면이 띄우는 ADK 공식 dev UI나 외부 ADK smoke 도구가 소비한다(워크벤치 자체 chat-smoke runner는 없다).

specialist / shared (agent_kind)

특정 도메인/임무 전용 agent / 여러 도메인에서 재사용하는 공통 agent.

State / Artifact / Event

ADK가 노드 사이 데이터 전달에 쓰는 채널. Graph IR edge_kind의 session_state, temp_state, user_state, app_state, artifact, event_output, event_message에 대응.

status

ModuleCandidate의 검토 상태. approved, deferred, rejected, needs_info.

stub runtime

generated runtime stub이 실제 모델/어댑터/은행 시스템 호출 없이 graph 구조와 wiring 경계만 검증하는 모드. 실제 business logic이 아니다.

Reuse Hub

/catalog route. reusable Agent/Workflow/Adapter/Remote A2A catalog를 검색하고 현재 root 후보에 pin하거나 catalog-delta.yaml proposal을 남긴다.

VerifyWorkbench

/af/:reqId/verify route. allow-list 검증 명령을 실행하고 manifest.validation.last_result, validation-report.md, catalog-delta.yaml evidence를 다룬다.

Taxonomy

워크벤치의 단일 분류 기준. module_category와 각 subtype enum. docs/workbench/taxonomy.md가 단일 활성 기준.

unknown

workflow_kind / adapter_kind / remote_contract_kind에 공통으로 있는 “증거 부족” 값. 새 enum을 만들지 말고 unknown으로 두고 needs_info에 남긴다.

workflow_kind

module_category: workflow일 때 subtype. orchestration, graph, dynamic, unknown 4개만 허용.
