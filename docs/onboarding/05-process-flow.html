5. Process Flow와 Graph IR

Process Flow는 AnalysisResult.processFlow에 저장되는 ADK 2.0 Graph IR artifact다. 필드 이름은 마이그레이션을 위해 processFlow를 유지하지만 내부 shape는 legacy stage-flow가 아니다. 이 장은 node / edge / container를 어떻게 읽고 어떻게 잘못된 그래프를 잡는지 본다.

워크플로우 패턴 → Graph IR

고정 순서

input → adapterA → adapterB → agent → output (edge_kind=event_output, execution_semantics=normal_transition)

병렬 fan-out/fan-in (container: parallel_region)

┌──► adapterA ───┐ input ──► router ────┤ ├──► join ──► agent ──► output └──► adapterB ───┘ (edge fan_out에서 시작 → fan_in으로 join에 들어옴)

반복 (container: loop_region)

input ──► agentDraft ──► loop_control ──► loop_back ──► agentRefine │ └── loop_exit ──► output (loop_control에서 평가, 조건 충족 시 loop_exit, 아니면 loop_back)

사람 검토 (container: human_review_region)

input ──► agent ──► human_input ──► router │ ┌── route_condition="approved" · route_aliases=["승인"] ──► output │ └── route_condition="rework" · is_default_route=true ──► agent (다시)

원격 에이전트 (container: remote_boundary)

input ──► agent ──[edge_kind=remote_a2a, a2a_contract_id=xxx]──► remote_a2a node ──► output │ (is_remote_boundary_crossing: true)

Validation — 꼭 잡히는 것들

  • parallel_region은 entry node가 2개 이상이고 join 경로가 있어야 한다.
  • loop_region은 loop_back과 loop_exit edge가 모두 있어야 한다.
  • human_input node는 downstream edge가 있어야 한다 (게이트를 지나간 다음 어디로 가는지 명시).
  • module-bound node는 incoming edge ≥ 1, outgoing edge ≥ 1. 고립된 노드는 scaffold-ready가 아니다.
  • remote_a2a edge는 is_remote_boundary_crossing: true와 a2a_contract_id가 필요하다.
  • 최종 id는 canonical 형식: edge는 edge-001, container는 container-root처럼. e-001, c-root는 final artifact에서 금지.
!

DesignWorkbench의 모듈 패널에서 저장하거나 Design Stage Runner 제안을 적용하면 Graph IR이 deterministic하게 재생성된다. analyzer 재실행이 아니라 현재 module candidates와 입력/출력 연결 기준으로 다시 만든다. 후보가 빠진 edge는 모듈 검토 순서대로 fallback edge를 보강한다. 그래도 incoming/outgoing이 없는 module-bound node가 남으면 validation error다. CLI source generator도 scaffold module이 Graph IR node로 덮이지 않으면 차단한다.

ADK source generation에서 Graph IR의 역할

ADK source bundle은 scaffold-plan.modules 배열 순서를 임의 실행 순서로 보지 않는다. 검토된 Graph IR의 edge를 기반으로 workflow skeleton edge를 만든다.

  • Graph IR input node는 generated workflow의 START와 연결된다.
  • module-bound node는 해당 stub node 함수로 변환된다.
  • Graph IR output node는 emit_workflow_result terminal node로 연결된다.
  • Graph IR에 없는 approved module은 source generation blocker다.

Graph IR marker 규칙

UI에 보이는 marker(parallel, human_review, loop, branch)는 별도 artifact가 아니라 Graph IR에서 파생되는 해석이다.

Marker판정 기준
parallelparallel_region 또는 fan_out/fan_in/join 존재
human_reviewhuman_review_region, node_kind: human_input, 또는 risk_signals: human_approval_required
looploop_region, loop_control, loop_back, loop_exit 존재
branchedge_kind: route 또는 route_condition 존재

새 marker가 필요하면 먼저 Graph IR의 어떤 node/container/edge semantics로 표현되는지부터 정의한 뒤, UI(glyph/label/색)는 별도로 작업한다.

퀴즈

Q1. DesignWorkbench에서 후보 5개를 모두 approved로 두고 Graph IR을 봤다. 그런데 후보 중 하나가 어떤 edge에도 연결되지 않은 채 노드만 화면에 떠 있다. 이 그래프는?

정답: Validation error. 고립된 모듈 노드는 scaffold source가 될 수 없다. DesignWorkbench의 모듈 패널로 돌아가서 입력/출력을 연결하거나 후보를 reject한다.

Q2. “초안 → 평가 → 품질 미달이면 다시 초안, 충족이면 종료”를 Graph IR로 그릴 때 사용하는 container는?

정답: loop_region. 정해진 종료 조건이 있는 반복은 static graph에서 loop_region + loop_control + loop_back + loop_exit으로 표현한다. 런타임에서야 분기 수가 결정되는 경우라면 dynamic_workflow를 검토한다.

Q3. 사람 승인 후 결과에 따라 “approved → output”, “rework → 다시 agent”로 보내는 edge는?

정답: route. 명시적 라우팅은 edge_kind: route이며 route_condition이 필수다. 사람이 입력할 승인/보완 문구는 route_aliases로 검토하고, fallback branch는 is_default_route로 하나만 둔다.

Q4. 독립 owner를 가진 원격 에이전트 노드와 본 그래프를 잇는 edge는?

정답: remote_a2a. 추가로 해당 노드를 감싸는 remote_boundary container와 A2A 계약 검토 화면에서 Agent Card/auth/timeout/retry/fallback/audit이 모두 준비되어 있어야 한다.
